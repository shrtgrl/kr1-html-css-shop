## Контрольная работа №1

Тема: «HTML и CSS: разработка многостраничного сайта».

Проект оформлен как интернет-магазин роялей и пианино **ReMi**.

### Что сделано в рамках контрольной работы

**Новые страницы**

- `order.html` — страница оформления заявки. Форма содержит имя, e-mail, телефон, выбор инструмента, комментарий и согласие на обработку данных. У всех полей есть `label`, обязательные поля помечены `required`, e-mail проверяется через `type="email"`, телефон через `type="tel"` и `pattern`.
- `product/` — отдельная страница для каждого из 6 инструментов: фото, описание, цена, кнопка заявки и таблица характеристик.

**Таблица характеристик**

- На каждой странице товара есть таблица `specs-table` с `caption`, `thead`, `tbody`, `th` и `td`, оформленная в CSS.

**Навигация**

- В меню всех страниц добавлен пункт «Заявка».
- На страницах товаров и заявки есть хлебные крошки.
- В карточках товаров появилась ссылка «Подробнее», которая ведёт на страницу товара, а кнопка «Заказать» ведёт на страницу заявки.

**Модальное окно**

- Окно быстрого просмотра товара `<dialog class="product-dialog">`: по клику на карточку показывает большое фото, описание и цену, а также ссылки «Подробнее» и «Заказать». Данные берутся из самой карточки, поэтому одно окно работает для всех товаров.

**Позиционирование**

- `position: relative` — карточка товара как опорный блок для бейджа;
- `position: absolute` + `z-index` — бейджи «Хит», «Скидка», «Новинка»;
- `position: sticky` — блок фильтров в каталоге остаётся на экране при прокрутке;
- `position: fixed` + `z-index` — кнопка «Наверх» на главной, в каталоге и контактах.

### Самостоятельные доработки

- собственная визуальная концепция: палитра, рукописный шрифт логотипа, фон шапки с клавишами рояля;
- фотографии товаров с прозрачным фоном;
- отдельная страница для каждого товара вместо одной общей;
- окно быстрого просмотра товара;
- бейджи и модификатор карточки `product-card--discount`;
- сообщение об успешной отправке заявки на чистом CSS через `:target`, без JavaScript;
- подсветка неверно заполненных полей через `:user-invalid`;
- блок «Что будет дальше» на странице заявки.
